# Wallet Butler 官网

这是一个无构建步骤、无外部依赖的静态站点，包含：

- 产品宣传首页
- 隐私政策
- 使用条款
- 支持与常见问题

所有网页、样式、脚本、manifest 和产品素材均平铺在 `website/` 根目录，不使用资源子文件夹。

## 产品素材

- `app-icon.webp`：由当前工程正式 AppIcon 压缩生成。
- `privacy-screen.webp`：由当前 iOS 模拟器构建截取的真实隐私引导界面，发布前需确认不含个人数据或设备标识。
- 首页账本设备是代码绘制的产品视觉预览，页面已明确标注，不作为已发布版本截图。

App 图标或界面改版后必须同步刷新对应 WebP，并重新检查桌面、手机裁切与图片清晰度。

## 本地预览

从仓库根目录运行：

```bash
python3 -m http.server 4173 --directory website
```

然后访问 `http://127.0.0.1:4173/`。

浏览器回归至少检查：

- 1440 × 1000 桌面尺寸
- 390 × 844 手机尺寸
- 移动导航展开和关闭
- 双设备首屏完整显示且页面无横向溢出
- 从首屏滚动到四个能力场景时，当前场景、章节进度、内部文案与视觉依次切换
- 桌面侧边章节进度保持粘性，手机顶部章节进度不遮挡导航或正文
- 首屏设备、能力场景与隐私设备视差不覆盖各自原有的缩放、旋转或定位
- 相邻区块背景和留白自然衔接，不出现无设计目的的突然明暗切换
- 宣传数字有清楚含义和事实依据；没有依据时使用直接文案
- 动画和滚动驱动状态在正常动态设置下实际运行；启用系统“减弱动态效果”后停止且内容仍完整显示
- 首页、隐私政策、使用条款和支持页互相跳转
- 浏览器控制台无错误

## GitHub Pages 发布

仓库已提供 `.github/workflows/deploy-pages.yml`。工作流在 `main` 分支的
`website/` 或部署配置发生变化时运行，并把 `website/` 直接作为 GitHub Pages
站点根目录发布；也可以在 Actions 页面手动运行。

首次发布：

1. 将仓库推送到 GitHub，默认分支保持为 `main`。
2. 在仓库 `Settings → Pages` 中把 `Build and deployment → Source` 设为
   `GitHub Actions`。
3. 推送一次包含官网的提交，或在 `Actions → Deploy website to GitHub Pages`
   中选择 `Run workflow`。
4. 部署完成后，从工作流的 `github-pages` environment 打开实际网址。

页面和素材全部使用相对路径，因此同时支持用户站点根路径和
`https://<user>.github.io/<repository>/` 形式的项目子路径。当前仓库未配置
自定义域名；取得正式域名后再新增 `CNAME`，不要提前写入占位域名。

站点自身不使用 Cookie、分析脚本、营销像素、表单或外部字体。GitHub Pages
作为首次托管服务时，仍需在公开发布前核对其当时有效的服务与隐私政策。

正式发布前必须：

1. 根据 GitHub Pages 的实际日志和政策复核隐私政策；切换托管服务时重新检查。
2. 确认 `kampui4app@163.com` 邮箱仍可正常收信，并将 App Store 下载按钮替换为真实地址。
3. 复核产品能力、系统版本、发布状态和隐私政策与最终 App 一致。
4. 补充正式经营主体、适用法律或其他发布地区要求的法定信息。
